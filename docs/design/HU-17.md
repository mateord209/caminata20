# Diseño HU-17 — Racha de días cumplidos consecutivos

**Responsable:** Thomas Montoya Magón · **Puntos:** 5 · **Sprint:** 2

## Estado actual

`RachaDiariaUseCase` calcula la racha en `domain/usecase/ComplianceUseCases.kt`, pero:

- Si hoy es día activo y aún no se alcanzó la meta, devuelve 0 (bug).
- No exime los días con Modo Reunión.
- Usa `Calendar.getInstance()` y `inicio + 86_400_000L` dentro del cálculo (difícil de testear y
  frágil ante cambios de horario).
- `HomeViewModel` no muestra racha; `MyDayViewModel` y `StatsViewModel` la calculan por separado.

La rama `origin/developRamirez-fixes` tiene una corrección parcial (commit `6e8f9e2`) que se toma
como referencia, pero se reimplementa con el diseño SOLID de este documento.

## Reglas de negocio (Adenda, CA-04..07)

1. Meta por defecto: 8 pausas.
2. Solo cuentan las pausas `COMPLETADA`; posponer no cuenta y la hidratación no cuenta.
3. Día no activo: neutro (no suma ni rompe).
4. Día con Modo Reunión: neutro.
5. Día en curso: no rompe la racha; solo suma si ya alcanzó la meta.
6. Día pasado activo sin meta: rompe la racha.
7. Meta efectiva = `min(metaDiaria, pausasEsperadas)`. En el modelo actual no hay ventana horaria,
   por lo que `pausasEsperadas = 24h/intervalo` y siempre es ≥ 8; la regla queda preparada para
   cuando exista ventana horaria. Los días de reunión se resuelven con la regla 4.

## Diseño

### Dominio

| Clase | Responsabilidad |
|---|---|
| `DayWindowCalculator` | Calcula inicio de día, fin de día y día de la semana con `TimeZone` inyectada. |
| `StreakDayEvaluator` | Clasifica un día en `COUNTED`, `NEUTRAL` o `BROKEN` según meta, día activo, reunión y si es hoy. |
| `CalculateStreakUseCase` | Recorre hasta 365 días usando el calculador y el evaluador. Sin Android. |
| `StreakResult` | `current`, `todayCompleted`, `todayGoal`, `atRisk`. |
| `MeetingDayRepository` | Interfaz: `days(): Flow<Set<Long>>`, `suspend fun mark(dayStart: Long)`, `suspend fun prune(before: Long)`. |
| `MarkMeetingDayUseCase` | Marca el día actual (y el siguiente si la reunión cruza medianoche) y poda >400 días. |
| `ObserveStreakUseCase` | Combina perfil + historial + horario + días de reunión y expone `Flow<StreakResult>`. |

### Datos

| Clase | Responsabilidad |
|---|---|
| `FirestoreMeetingDayRepository` | Documento `users/{uid}/settings/meetingDays` con `days: [epochDayStart]`. Usa `arrayUnion` y la caché persistente de Firestore como caché local. |
| `FirestorePreferencesRepository` | Sin cambios; el horario sigue saliendo de `settings/preferences`. |

### UI

| Clase | Responsabilidad |
|---|---|
| `StreakCard` | Composable stateless: racha actual, progreso de hoy y estado “en riesgo”. |
| `HomeViewModel` | Consume `ObserveStreakUseCase`; no calcula reglas. |
| `MyDayViewModel` / `StatsViewModel` | Reutilizan `ObserveStreakUseCase` para eliminar duplicación. |

## Riesgos

- El documento `meetingDays` crece con el uso; se poda a 400 días.
- Si el usuario activa Modo Reunión y desinstala antes de sincronizar, el día no se marca; es
  aceptable para el MVP.
- La meta efectiva completa requiere ventana horaria; se documenta la simplificación.
